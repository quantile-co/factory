## Confirmed failure mechanism and implementation choice

#lesson [[factory-ci-stall]]

One reproduced setup stall was directly confirmed as a fork-inherited Nix
interrupt-callback registry mutex: the child retained a locked registry with
an owner absent from its threads, while the parent's copy was unlocked. The
worker's call chain matched `createInterruptCallback` and file transfer,
consistent with upstream NixOS/nix#16581. This confirms that case, not every
historical timeout. Other jobs had progressing downloads or ordinary failures;
output silence alone is not a deadlock diagnosis.

The user rejected a maintained Nix fork/backport. The dated upstream audit did
not establish an available fixed release or a usable known-safe downgrade.
Changing standalone Nix would not replace the library embedded in devenv.
HTTP tuning, privileges, sandbox changes, and daemon selection were not
established repairs. The environmental cause of the higher observed Namespace
failure frequency remained unresolved.

QMD's pinned upstream packaging deliberately replaced ordinary bun2nix
`fetchurl` with `builtin:fetchurl`. External builders execute before downloading,
avoiding that known inherited-registry path. Pi already used external npm-based
packaging. This justified a targeted package override, not a claim that all Nix
fork hazards or all historical timeouts were eliminated.
