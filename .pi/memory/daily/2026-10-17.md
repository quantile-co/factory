## Confirmed failure mechanism and implementation choice

#lesson [[factory-ci-stall]]

One reproduced setup stall was directly confirmed as a fork-inherited Nix
interrupt-callback registry mutex: the child retained a locked registry with
an owner absent from its threads, while the parent's copy was unlocked. The
worker's call chain matched `createInterruptCallback` and file transfer,
consistent with upstream NixOS/nix#16581. This confirms that case, not every
historical timeout. Other jobs had progressing downloads or ordinary failures;
output silence alone is not a deadlock diagnosis.

The user rejected a maintained Nix fork/backport. The dated upstream audit did
not establish an available fixed release or a usable known-safe downgrade.
Changing standalone Nix would not replace the library embedded in devenv.
HTTP tuning, privileges, sandbox changes, and daemon selection were not
established repairs. The environmental cause of the higher observed Namespace
failure frequency remained unresolved.

QMD's pinned upstream packaging deliberately replaced ordinary bun2nix
`fetchurl` with `builtin:fetchurl`. External builders execute before downloading,
avoiding that known inherited-registry path. Pi already used external npm-based
packaging. This justified a targeted package override, not a claim that all Nix
fork hazards or all historical timeouts were eliminated.

## SecretSpec runtime delivery

#decision #implementation [[factory-secretspec]]

Historical discussion established why transparent runtime exports were chosen:
mapping resolved secrets into Nix `env` had placed synthetic values in
world-readable shell/derivation outputs. Native `secretspec run` worked,
including exit/signal handling, but required downstream wrappers and repeated
resolution. The user preferred provider switching and automatic inheritance by
ordinary shells/tasks. The old exporter was 38 lines and one option, not a broad
framework. No historical manifest used `as_path`; lifecycle handling was
explicitly deferred. Those historical tests do not substitute for current-pin
validation.

Implementation landed as `5b0006be5af4227caf0f14a99c30f9277cf6eb0f`:
`etc/secretspec/secretspec.toml` and `nix/secretspec/{default.nix,default.test.ts}`,
with package/config/hook options and explicit root opt-in. Native Devenv
SecretSpec resolution stays disabled. `SECRETSPEC_FILE` selects the store-backed
manifest; no generated root manifest, bootstrap bypass, or missing-file skip is
needed. Only declarations enter Nix outputs; runtime loading fails before child
execution if required inputs are missing.

Default/check are credential-free. Test/Plan/Apply explicitly require and pass
the Cachix publication token; action input alone does not populate task env.
Production inputs and existing WIF, authorization, locking, and exact-plan
safeguards remain unchanged. No scopes or ambient credential-clearing behavior
were added.

Fresh tests disproved the assumption that generated files precede shell capture:
shell environment capture happens before `devenv:files`, and direct tasks do not
implicitly run that task. Store-backed declarations avoid this dependency.
File-provider paths are manifest-relative, so store-backed manifests need
absolute runtime provider-file paths. Consumers may seed a root manifest and
remove `SECRETSPEC_FILE` for native discovery.

Synthetic tests cover shell/dependent-task inheritance without a root manifest,
provider switching, multiline/metacharacter quoting, tracing restoration,
missing-input failure before child execution, credential-free default, and
selected shell/derivation/log non-leakage. They do not claim zero transient disk
exposure. A separate profile exercise accepted all five profiles and rejected
each missing required input: test one, plan nine, apply nine. Six tests passed
locally. Exact-head Check `39097523158` passed in 71s; post-merge main Test
`39097629433` passed in 86s, including cache post steps. No Plan/Apply ran.
