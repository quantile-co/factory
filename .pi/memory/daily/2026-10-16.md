omits duplicated handoffs, private cross-repository details, raw diagnostic

## Tooling and dependency workflow

#decision [[factory-workflow-boundary]] [[factory-moving-flake-refs]]

- Kept tool packages reusable outside devenv and CI. Native tool templates live
  under `etc/`; consumers own placement and configuration. Terraform source and
  tests stay native HCL, Rego, and TypeScript, with Nix wrappers outside `tf/`.
- Kept pinned pnpm and the root pnpm lock for TypeScript/Vitest, while preserving
  Pi's separate ignored npm-managed packages.
- Chose repository direnv configuration for Pi memory routing instead of a
  global routing extension. Reviewed daily logs may be committed; scratchpad,
  recovery data, raw sessions, and sensitive material must stay out of Git.
- Rejected workflow tests that duplicate YAML literals or third-party actions.
  Actionlint, policy checks against real source, behavior-focused integration
  tests, and ordinary CI runs remain the validation layers.
- Reviewed the old Update workflow and wrappers; Dependabot supersedes them.
  Moving flake references retain exact committed lock revisions. The Nix updater
  cannot maintain `devenv.lock` and does not guarantee atomic paired updates;
  CI checks both the working locks and Git index for drift.

## Runner migration and cache locality

#implementation [[factory-namespace-profiles]] [[factory-cache-locality]]

Size-specific runner profiles and workflow labels were introduced without
broadening Restricted access, main-only cache publication, or the separate
20 GiB profile/repository cache identities. Factory temporarily selected 8x16
in PR #14 (`cd57abf`), removed its temporary tracing, and restored the ordinary
10-minute Check. PR #15 was closed as superseded. This size selection was later
replaced by 4x8 on October 17.

The user required Test to run Check first. The actual
`tasks run --mode before test:all` invocation validated that dependency locally
and on main. Temporary tracing could change timing; a green instrumented run
was not treated as a fix for the intermittent setup stall. Slow but progressing
transfers, actual check failures, and motionless setup stalls were distinguished.
No speculative HTTP, retry, privilege, or transfer-timeout tuning was adopted.

Initial all-cold observations led to a publication-failure hypothesis, which
was corrected after read-only provider-lineage inspection. Publication and
restoration both worked. Misses could result from no suitable parent on the
assigned node; preallocation also means attachment can precede an earlier
job's publication. Neither the cache-action success message nor sequential
workflow dispatch guarantees a hit. Capacity and cache-write policy were not
changed to mask locality. The user declined provider support outreach.

## Old-directory review and cache design

#decision [[factory-old-devenv]] [[factory-cachix-policy]]

Reviewed the old Build workflow: it realized the selected environment and ran
tests, rather than building every exported package. Chose to reuse legitimate
Check/Test work instead of porting a separate cache-warming Build. Test realizes
its selected shell/check/test dependencies, including production wrapper
packages without executing those wrappers. It does not cover every platform,
unselected export, or runtime download outside the Nix store.

Old top-level `tf/` had been reviewed; `devenv/tf/` remains separate. Continue
old-directory review one directory at a time, with approval before each port.
The pending inventory is retained in project memory. Do not revive the removed
member-landing ruleset, old Update harness, or obsolete workflow waivers.

The existing public Quantile Cachix cache was audited. Runtime organization
credential configuration was prepared separately from Terraform payloads; no
credential bytes were committed. Existing cache hits or a no-op upload do not
prove a fresh write succeeded. Shared cache writers are a supply-chain trust
boundary, and main-only workflow conditions do not make organization secrets
inherently main-only. Clearing a remote cache alone does not remove compromised
copies already restored elsewhere.

The final approved Factory design keeps public cache reads in Check and
main-only uploads in Test, Plan, and Apply. Use the standard Cachix store scan,
not a custom `cache:push` task or explicit root collection. The scan captures
new paths, not an arbitrary previously restored store. Namespace publication
also remains provider-enforced main-only. Continuous batched Test with bisect,
revert/fix-forward preparation, and escalation was recorded as a TODO only.

## Fork approval and production-source safety

#implementation [[factory-fork-approval]] [[factory-production-flake-source]]

Prepared mandatory `all_external_contributors` approval in `tf/project` using
the reviewed REST API provider because the GitHub provider lacked this setting.
Kept runtime bearer authentication caller-owned and the registry source/lock
that supplies the provider signature. The singleton uses PUT for reconciliation
and non-mutating removal so deleting the Terraform resource does not loosen
remote approval. Local validation covered initial application, clean planning,
out-of-band drift, saved-plan repair, and removal; the bearer was absent from
state. Existing Rego and Vitest coverage was extended without committing a
separate diagnostic harness. Local checks and all four integration tests passed.

Adding Cachix publication to production workflows exposed an important source
boundary: a synthetic `path:.` input included ignored credential, backend, and
saved-plan files. Git-aware flake input excluded them. Plan/Apply bootstrap now
uses `nix run .#devenv-cli`; protected-main, actor/rerun, environment, WIF,
locking, concurrency, and exact-saved-plan safeguards were preserved.

No production Plan/Apply was authorized by these source changes. Fresh cache
publication and live approval reconciliation were still pending at this day's
implementation stage; later rollout results are recorded separately.
